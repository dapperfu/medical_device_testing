Training mock · software safety class C

Mock humans, exercised against mock devices, on every change.

This project shows a closed loop: fixture patients stand in for humans, device software reads their vital signs, pytest checks the result against written requirements, and GitHub Actions runs that suite on every push and pull request.

This site is a training record. It is not a conformity claim, a certification, or a regulatory submission. Class C was confirmed for the exercise on 2026-10-20.

The project

A small vital-signs patient monitor and two remote patient readers. The humans are Python fixtures. The devices are the software under test. Nothing here is a real monitor or a real patient.

Mock humans

Each patient is a subclass of Human with a fixed age, vitals, and sensor state. Tests use a new instance every time.

  • Healthy adult
  • Tachycardic adult
  • Hypoxic adult
  • Hypertensive adult
  • Pediatric patient
  • Sensor-fault patient

Devices under test

  • Patient monitor — attaches a patient, selects adult or pediatric alarm limits by age, and raises vital-sign or sensor-fault alarms.
  • SOAP patient device — reads the same fields from a local SOAP 1.1 GetPatient stub.
  • ReadyAPI patient device — reads them from GET /patients/{patient_id} on readyapi 0.112.0. The workflow does not install SmartBear ReadyAPI.

Closed loop in GitHub Actions

Requirements name the behavior. Tests verify it. Continuous integration runs the tests and keeps the HTML report. Trace links point from a failing check back to the requirement it was written for.

  1. 01

    Requirements

    StrictDoc sources in requirements/ state what the monitor, the interfaces, and the harness shall do.

  2. 02

    Mock closed loop

    A fixture human is acquired in process, over SOAP, or over ReadyAPI, then attached to the monitor.

  3. 03

    Pytest

    make test runs unit, then integration, then system tests and writes docs/pytest-report.html.

  4. 04

    GitHub Actions

    On push and pull request, the workflow runs that same command and archives the report, including when the run fails.
