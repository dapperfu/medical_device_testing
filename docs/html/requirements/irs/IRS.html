    1. Patient monitor interface

    IRS001
    1.1. attach
    UID: IRS001
    RELATIONS (Parent):
    • SSS005 Attach selects the default profile
    STATEMENT:

    attach shall accept a Human and shall select the default limit profile for that patient's age.
    IRS002
    1.2. start and stop
    UID: IRS002
    RELATIONS (Parent):
    • SSS004 Idle and stopped monitor
    STATEMENT:

    start shall begin monitoring when a patient is attached and shall reject a start when no patient is attached. stop shall end monitoring.
    IRS003
    1.3. set_limits
    UID: IRS003
    RELATIONS (Parent):
    • SSS007 Reject out-of-range limit command
    STATEMENT:

    set_limits shall accept an in-range AlarmLimits and shall raise LimitRejected without changing the limits already in effect when the command is out of range.
    IRS004
    1.4. vitals and alarms
    UID: IRS004
    RELATIONS (Parent):
    • SSS001 Report five vital values
    • SSS006 Sensor fault risk control
    STATEMENT:

    vitals shall return a reading whose valid flag is true only while monitoring is running with a valid sensor. alarms shall return the active alarm set and shall return an empty set when monitoring is not running.
    IRS005
    1.5. SOAP GetPatient
    UID: IRS005
    RELATIONS (Parent):
    • SSS010 SOAP GetPatient returns a Human
    • SSS011 SOAP fault does not return a patient
    STATEMENT:

    GetPatient shall accept a patientId and shall return that patient's identity, age, vitals, and sensor validity, or a SOAP fault when the patient is unknown or the request is malformed.
    IRS006
    1.6. ReadyAPI patient resource
    UID: IRS006
    RELATIONS (Parent):
    • SSS012 ReadyAPI patient resource returns a Human
    • SSS013 Unknown ReadyAPI patient does not return a patient
    STATEMENT:

    GET /patients/{patient_id} shall return that patient's identity, age, vitals, and sensor validity as JSON, or status 404 when the patient is unknown.
